# 三视图 → 完整部件贴图

输入同一角色的正面、侧面、背面图，以及需要的部件清单和实际显示尺寸。输出每个目标视图的独立透明 PNG、画布与裁切位置清单、重合成检查图。每件应能单独查看，保留被遮挡区域和完整轮廓；部件之间允许重叠。

本技能以 `game-asset-spine-portrait` 的贴图方法和执行顺序为基础，扩展到三视图与不同执行方式，执行到重合成验收为止。来源与适配边界见 [sources.md](references/sources.md)。服务地址、凭据、模型选择和项目路径由使用者的项目级技能或配置提供；不需要作者的本机环境。

## 1. 先比较方案，再选工具路线

先用同一张基础图试一组代表性部件（头发、脸、衣身、手臂），比较语义正确性、遮挡补全和画布一致性，再扩大到整套部件。上游最终采用 See-through；同画布逐部件编辑是另一条可选路线。早期像素差分切层已被上游否定，不能因为旧脚本存在就把它作为默认方法。

**先区分两条技术路线，再选执行入口：**

- **A · See-through 专用模型路线**：部署并运行 LayerDiff / Marigold，生成语义层与深度。本地部署可选官方 Python 或 ComfyUI 封装，需要相应推理环境。
- **B · 通用生图 / 改图 API 路线**：通过文生图、图生图 / 编辑请求逐件制作完整 RGBA；使用云端服务时本机不运行这些生成模型，只负责请求、文件处理、对齐与验收。不要求先跑 A，也不限于给 A 补件。

B 可以以相同的完整部件与重合成效果为目标，但不等于运行或复现 See-through 模型。文生图适合候选设计，已有角色拆件优先图生图以保持身份与造型；跨请求的位置、比例、轮廓与 alpha 都需核对。通用 API 通常不提供可比逐像素深度，此时记录明确的前后顺序，不伪造深度。两条路线可以独立使用，也可在记录来源后组合。

“本地 / 云端”是部署选择，不是算法的绝对边界：See-through 也能远程部署，通用图像模型也能本地部署。项目级指针应明确本项目选哪一条，不能因默认 API 未提供深度就自动安装本地 See-through。

| 执行方式 | 对应方法与用途 | 需要核对 |
| --- | --- | --- |
| See-through 官方 Python | 独立运行语义分层与深度推理，直接导出部件文件或分层 PSD | 按官方说明准备 Python、PyTorch、依赖与模型；从官方仓库根目录运行，记录源码修订、参数、pad/resize 变换；命令见配套参考 |
| ComfyUI（可选） | 用 See-through 节点封装相同分层能力，也可接入其他图像编辑工作流 | 按现场 `/object_info` 核对节点输入；记录节点、模型、工作流版本；节点补丁只在采用该封装时检查 |
| 生图 / 改图 API | 带原图逐部件编辑，在同一画布上只保留并补全指定部件；文生图可做候选 | 先确认服务是否支持参考图、编辑、mask、透明输出；请求尺寸和 alpha 不保证被遵守，必须读回检查 |
| 生视频 API | 按需生成转身或局部显露片段，抽取稳定帧辅助理解遮挡，再经分层或图像编辑得到独立 RGBA | 视频通常只有合成画面，不会直接交付分层；记录帧与时间点，检查身份、轮廓、压缩和漂移 |

官方在线演示可作为免本机安装的 See-through 入口；使用前核对可用状态与导出格式。所有入口都接回步骤 2–7，不要求先安装 ComfyUI。

生视频是本技能扩展的参考路线，不是上游已经验证的拆层替代品。已有足够三视图时不必额外生成视频，也不在本段制作成品动画。工具能力不足时明确记录缺项，换用可行路线，不把请求成功当成部件完成。

执行前按需读取 [parts-sheet-prompt.md](references/parts-sheet-prompt.md)：含单件提取、补全提示词和各工具接入。处理透明边缘、跨视图对齐或重合成验收时读取 [quality-checks.md](references/quality-checks.md)：含操作步骤、诊断字段和失败边界。

## 2. 准备基础图与部件清单

1. 确认角色、目标视图、实际显示尺寸和目标部件。默认处理已提供的正 / 侧 / 背；只要求某一视图时，另外两张用于参考。
2. 每个视图使用自己的基础画布，记录尺寸、朝向、输入文件及 SHA-256；不同视图可以分辨率不同。跨视图参考用于理解结构，不能把背面头发直接挤压成正面轮廓。
3. 双手与衣身分开；逐一描述尾巴、翅膀、发饰的位置与形状。按使用需求细分头发、脸、眼白、虹膜、嘴、衣身和四肢，不机械套用固定部件数。
4. 明确左右指角色自身左右，记录侧面朝向；背面不应生成正面五官，真正不可见且无需单独使用的部件可标为不适用。
5. 检查基础图透明度、底色残留和细发丝。保留真实半透明，不批量把接近不透明的 alpha 改为 255，不盲目删除小饰物或填平发丝间隙。

记录视图一致性卡：身份与不对称饰物、相机方向、头顶、眼 / 耳、肩、腰、脚底及相同服装特征；记录哪些位置可从该视图观察、哪些是推测。已有三视图直接检查，不强制重生；缺视图时才比较同画布多栏与身份主图加标志卡分别生成，结果要逐视图验收。

同画布局部编辑要锁定画布、姿态、头部位置及非目标区域。局部编辑保留其他部件；单件提取则把非目标部件移除成透明，这两种任务要分开下指令。表情或手势变体只有在明确需要对应贴图时才做，不扩展到驱动与动画。

## 3. 生成语义部件，先检完整性

1. 用选定方案输出每个部件的完整 RGBA：除当前可见部分，还要有被头发、袖口、衣身等遮住的延伸区域与自身描边。
2. 逐件单独检查，再与清单核对。分辨率高不代表部件全；缺裙子、头饰或肢体时先换种子、较低分辨率或重新描述，再以完整层替换。
3. 保留生成层的完整轮廓。不要只截取原图可见部分，不把原图颜色差分当部件，也不要把生成层的可见部分换回原图像素来掩盖重合成误差。
4. 部件之间允许有遮挡重叠。若保留标签图，它只辅助诊断原图可见区域，不能约束完整层“一像素只能属于一件”，也不能用它裁掉补全区域。
5. 如有逐像素深度，连同本次运行标识保存。不同次推理的深度标尺不能直接互比；替换层后先复核相对遮挡，必要时统一推理或人工确定前后关系。

一次推理输出的“层”可能只是颜色或阴影分组，必须重新检查人体与服装语义。逐件确认被遮住处补到哪里（例如腿至髋部、衣身至肩侧、后发至脸后）、轮廓是否完整；遮挡内容是推测，不冒充真实观测。单件图要实际检查 alpha 和纯色背景残留，细节见质量检查参考。无法可靠补全的部件写入待处理清单，不能靠超分、锐化或填色块宣称完成。

## 4. 按需提高局部清晰度

先通过层完整性检查，再处理头部、眼睛、嘴和发饰等局部清晰度。

- 若使用节点的高清头部补丁，先核对节点版本并执行补丁兼容检查；本技能不附带作者机器上的补丁或权重。
- 高清结果若通过 `latest.txt` 等共享记录取回，要串行运行、核对本次运行与输出路径。背面无脸时记录可能不更新，不得复用上一张脸。
- 上采样改善清晰度，不能补缺件或修正轮廓；优先重新生成完整高质量层，避免把缺失放大。
- 保留原始输出与变换记录，不把历史显存推测写成当前硬件实测能力。

## 5. 还原统一画布并导出独立 PNG

1. 对每个视图，按该次推理真实的 padding、resize、裁切记录，把所有层还原到基础图画布。禁止凭外观猜缩放，或将各件分别拉伸到看似合适的尺寸。
2. 需要重采样时使用预乘 alpha：先将 RGB 乘 alpha，RGB 与 alpha 一起重采样，再在 alpha 非零处解除预乘，减少透明边缘黑边 / 白边。交付时声明 PNG 的 alpha 约定。
3. 保留完整 RGBA，虹膜、嘴等局部也包含自己的颜色与 alpha；不把原图整块背景带进局部层。
4. 先保存同画布层用于重合成；交付可保持全画布，或裁掉透明外边后记录准确 `offset`。裁切只是导出优化，不是回到“原图直切拆层”。
5. 裁切框使用半开区间 `[x0,y0,x1,y1)`，`size = [x1-x0,y1-y0]`，`offset = [x0,y0]`，包含实际 padding。全画布层的 offset 为 `[0,0]`。不要固定减 2px 来推算位置。

建议输出布局（在使用者的工作目录中创建，不写入已安装技能目录）：

```text
<character>/parts/
├── front/
│   ├── base.png
│   ├── layers/<part>.png
│   ├── composite.png
│   └── difference.png
├── side/                         # 同上
├── back/                         # 同上
└── manifest.json
```

## 6. 先重合成，再交付贴图

按记录的位置把每件放回对应视图。前后关系固定时按明确的从后到前顺序做 alpha 合成；有可比的逐像素深度时，按深度决定遮挡并做 alpha 合成。若同一部件一部分需在衣身后、另一部分需在衣身前，单一图层顺序不能表达：重新规划前 / 后件或标记待处理，不能编造深度。记录实际使用的方法，不假装所有 API 都返回深度。

检查顺序：

1. **缺层与重复层**：裙子、头饰、双手、尾巴有没有漏掉；是否夹带一张完整角色导致重复身体。
2. **位置与轮廓**：原尺寸和实际显示尺寸下检查头部、手腕、肩颈、发际线；侧面和背面单独核对，不拿正面轮廓强套。
3. **遮挡与边缘**：被遮挡区域是否补全、前后顺序是否正确、透明缝与杂边是否可见。
4. **重合成差异**：把基础图与重合成结果放到相同背景、相同颜色处理下比较。报告 RGB 平均绝对差（0–255）、前景轮廓 IoU，以及 `alpha_miss`；说明统计区域和 alpha 阈值。`alpha_miss` 可定义为基础图前景中被重合成漏掉的像素比例，分母不是整张画布；基础图没有可靠透明背景时，先核验去背或人工前景 mask，无法可靠确定则指标记为无法计算。输出缺口图及按区域定位的框、面积和临近部件候选，以便定向修复；无可靠归因时标未知。
5. **局部编辑范围**：仅对“保留其他区域的局部编辑”比较未编辑区域差异；不要拿单件层与整人图算全图 IoU。提示词不能保证 ROI 外逐像素不变，要实际检查并记录结果。

上游历史参考为重合成误差约 12/255、`alpha_miss` 约 1%，局部对齐曾以偏移 <0.5px、IoU >0.99 为目标。这些用于触发缺层、错位排查，不是所有角色的统一通过线；误差定义与统计区域不同也不能直接互比。按角色、画风、分辨率和实际显示尺寸确定本次门槛，并保存视觉证据。

**不要求生成式完整层逐像素还原原图，也不要求部件覆盖次数恒为 1。** 即使误差低，缺件、错误人体语义或破损轮廓仍需修复。未通过的候选可以留作工作文件，交付清单必须区分已验收和待处理。

## 7. 记录清单并结束本段

清单最少记录：输入与哈希、视图及画布、语义件名、文件及哈希、尺寸和 offset、遮挡顺序或深度来源、生成来源及变换、验收结果和未解决项。示例是本技能建议的贴图交换格式，不冒充某个下游程序的既有协议：

```json
{
  "schemaVersion": 1,
  "character": "example",
  "alphaMode": "straight",
  "views": {
    "front": {
      "base": { "file": "front/base.png", "size": [1024, 1536], "sha256": "<sha256>" },
      "parts": [
        {
          "name": "hair-back",
          "file": "front/layers/hair-back.png",
          "size": [600, 1000],
          "offset": [200, 100],
          "sha256": "<sha256>",
          "source": { "method": "semantic-layers", "runId": "<run-id>" }
        }
      ],
      "composition": { "method": "alpha-over", "backToFront": ["hair-back"] },
      "validation": { "status": "pending", "unresolved": ["示例只列一个部件，未完成整人重合成"] }
    }
  }
}
```

文件、提示词、模型 / 工作流版本、pad/resize 变换、运行标识与深度来源可存附属记录，并在清单引用。重新生成或编辑后同步哈希；保留上一版以便比较，不删除无关资产。

交付：逐件贴图、清单、重合成 / 差异图、通过情况及缺项。到此结束；不生成骨骼、网格、图集或运行时代码。

## 失败时优先排查

- 爆炸图曾保留整人且漏部件，不能把它定为默认正式路线。
- Qwen-Image-Layered 的历史试验曾按色彩 / 阴影拆层；核对语义再使用，不将一次失败泛化为所有版本都不可用。
- 通用矢量化会破坏渐变、睫毛与虹膜；不要作为默认清理步骤。
- 把完整层裁成原图可见区域、强压回原图像素，会丢失遮挡补全；回到完整层重新验收。
- 深度标尺混用、pad/resize 逆变换遗漏、取到上一轮高清脸，都会让清晰的贴图仍然无法正确合成。
