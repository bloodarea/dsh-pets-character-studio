# 立绘问题标注

打开立绘或拆件工程，圈出哪里有问题，写一句修改要求。默认界面只用于反馈问题。

## 开始使用

只需 Python 3，无需安装其他依赖。

- Windows：双击 `start.bat`。
- macOS / Linux：运行 `./tools/part-annotator/start.sh`。
- 浏览器地址：<http://127.0.0.1:8123/tools/part-annotator/>。

已有服务时直接打开地址即可。也可以重复运行启动脚本：**如果 8123 上占着的正是本工具自己的旧实例，
会先结束它再接管端口**（不会碰别的程序），所以不用手动找进程、也不用换端口。`--port 9000` 可指定端口。
也可以在仓库根目录运行：

```bash
python tools/part-annotator/serve.py --no-browser
python tools/part-annotator/serve.py --port 9000 --no-browser   # 换端口
python tools/part-annotator/serve.py --no-restart               # 不结束旧实例，直接换空闲端口
python tools/part-annotator/serve.py --strict-port              # 端口被别人占就报错退出，不换端口
```

端口被**其它程序**占着时不会去杀它：会打印占用者（PID + 命令行）并自动改用下一个空闲端口；
要它直接失败就用 `--strict-port`。

Windows 找不到 Python 时，可设置 `DSH_PETS_PYTHON` 为解释器完整路径；否则依次尝试 `py -3`、`python`。
页面更新后刷新即可（服务对页面与脚本都返回 `no-store`，不会吃到旧缓存；早期版本留下的缓存按一次 Ctrl+F5）。

## 记录一条问题

1. **打开拆件工程**，点 **添加问题**。问题必须指向一个已拆分的部件；只打开图片时不能添加问题
   （先「打开拆件工程」，或把工程文件夹拖进来）。
2. **选择有问题的部件**（第 1 步下拉）。这就是「改动前」：表示问题发生在哪一件，
   不需要再画「改动前」选区；工具会自动保留该件的可见区作为参考。
3. 用 **矩形框选、多边形框选、魔棒或画笔** 标记位置，可连续标多块，也可以来回切换目标继续加。
   面板会实时给出坐标：拖的时候显示**当前选区 x,y · 宽×高**，落下后显示**已标记 x,y · 宽×高（像素数）**。
   **只点一下不算选区**（不拖出面积就当没选），不会多出 1px 的杂块。
4. **写一句哪里需要改**，点 **保存标注**。

圈错了点“撤销”，或用橡皮擦擦掉标记；圈好了点“完成圈选”。橡皮擦不会修改原图。
“补充要求”可选：可以圈出**期望范围**（改动后该有哪些像素，画不完整也没关系），
或选择问题类型、优先级；不确定就写在说明里。
未圈出位置或未选部件的问题会提示补充，或删除这条问题后再保存。

## 看部件

右侧“部件”页列出全部部件（上=更靠前），每行带像素数与眼睛：

- **眼睛**：只看或隐藏这一件（隐藏只影响显示，不改拆分结果）。在双/四视图里，眼睛只改变
  「部件叠加」格，左边/上面那几张立绘保持原样。
- **部件颜色**：工具栏勾选后按部件给画面上色，一眼看出每块归谁；隐藏的部件不上色。
  单视图里画在画布上；**双视图 / 四视图里画在「部件叠加」那一格**，三张立绘保持纯静态图。
- **点一行**：把它设为当前问题的问题部件，再回“问题”页圈位置。
- **选中高亮**：选中哪一件，画面上就给这件**按它自己的配色铺一层**（强度接近“部件颜色”的色块）再描一圈白边 ——
  **「部件颜色」没勾也照样显示**（勾了则只补白边，不重复上色）。双/四视图里这条高亮画在「部件叠加」格。
- **再点一次同一件 = 取消选择**（高亮消失，问题关联不变）。
- 点“只看这个部件”可单独显示该件；此时不叠加部件颜色。
- 搜索框按名称过滤；`▲▼` 调层级在“高级编辑”里。

## 视图：单 / 双 / 四

工具栏右侧是三选一的分页选择器，打开工程后默认回到 **单视图**：

| 视图 | 内容 |
| --- | --- |
| 单视图 | 当前这张图，正常标注 |
| 双视图 | 左：原立绘；右：部件叠加 —— **两格都能直接圈选**（共用同一套坐标） |
| 四视图 | 正面立绘 / 侧面立绘 / 背面立绘（三张静态图）+ 部件叠加 |

四视图的规则：

- 三张立绘只是**静态图片**，点一下算选中它（绿框，默认正面），「部件叠加」跟着显示该视图的拆件。
  四视图里只有**当前拆件包对应的那张**（现在=正面）可以标注，其它两张纯对照；
  **双视图则两格都能圈选**（左原图、右叠加图），拖在哪一格虚线框就画在哪一格。
- **三张立绘永远是原图，不会跟着变**：部件页的眼睛（显隐）、「部件颜色」、「完整部件」底图切换，
  在双视图 / 四视图里**只作用于「部件叠加」那一格**（单视图则作用于整块画布）。
  所以想看「隐藏某件之后下面是什么」，看部件叠加；立绘那边始终是原始参考图。
- **只有“部件叠加”这一格会变**：它显示**当前选中立绘**的拆件叠加结果。选中侧面 / 背面而该视图没有拆分件时，
  这一格显示空视图并写明“侧面立绘还没有拆分件”，不会画错东西。
- 三张图里只有**当前拆件包对应的那张**（现在就是正面）可以标注，其它两张纯对照。
- **四格共用同一套缩放/位移**，所以坐标始终对齐：只有**「部件叠加」那一格**接受操作 ——
  滚轮缩放在指针处、用「移动」(V) 拖 / 空格拖 / 中键拖平移；三张立绘**跟着一起动**，不能各自跑。
  双击任意一格 = 四格一起重新适配。
- **位置联动点**：光标停在「部件叠加」上时，对应的那张立绘会在同一像素位置显示一个绿点（反过来也成立），
  方便看清“这块在立绘的哪里”。双视图和四视图都有；单视图本来就只有一张图，不需要。
- **放大镜**：按住 **Alt** 在指针处显示约 3 倍圆形放大镜（任意一格都可用），松开即消失，用来核对 1–2 px 的毛边。
- **部件叠加**不是把原图复制一遍：它按 z 序把每件的 `layers/<id>.png`（含被遮挡补全）重新叠起来，
  等于把拆出来的完整部件拼回去。隐藏某件时露出来的是下面那层的完整部件，不会像直接抠原图那样留下一个洞。
- 侧面 / 背面图来自 `assets/source/<角色>/three-view/{side,back}.png`；没有这张图时格子中间显示占位文字。

## 完整部件底图

工具栏的 **完整部件** 开关（默认开）决定“底图”用哪个：

- 开：用部件层叠图当底图 —— 看得见被遮挡部分，隐藏某件会露出下一层；
- 关：用纯原立绘（隐藏某件会把它从画面里抠掉，露出透明格）。

两者都不改数据：保存的仍是 `masks/` 的可见区真值与 `layers/` 的成品层。

## 保存在哪里

继续使用 `parts-bundle v1` 格式，已有工程可以直接打开。
保存目标为 `workspace/characters/<角色>/parts-bundles/<工程名>/`。
在该目录打开的工程保存到原处；从其他目录打开时也会保存到此标准目录。
第一次保存需要命名；文件菜单可另存工程或导出 ZIP。

一个工程是一个文件夹，以 `index.json` 为入口，包含原图、部件和问题记录。
问题记录存入 `issues.json` 及对应区域图片；选择部件时自动保留该件的参考信息。
这些数据概念无需在标注时操作。完整格式见 [BUNDLE.md](BUNDLE.md)。

打开工程需要通过本地服务，直接双击 `index.json` 无法读取同目录图片。
工程放在本地 `workspace/`，不会随工具源码提交。

## 高级编辑

右上角“高级编辑”保留原来的部件新建、合并、删除、层级调整及可见区/补全编辑。
需要调整拆分数据时再进入，点“返回问题标注”回到简单界面。
简单界面的圈选、画笔和橡皮擦只修改问题标记。

工具不执行图像生成或自动修图。保存不会清除旧工程中的孤立文件，需要干净副本可另存新工程。

```bash
node tools/part-annotator/selftest-node.mjs
# 或浏览器打开 tools/part-annotator/selftest.html
```

核心与格式自测共 33 项。简单流程另用真实 Chrome 输入验证：部件选择、连续框选、
停止圈选、切换目标、画笔/橡皮擦撤销、说明框快捷保存、保存重开、问题删除撤销和窄屏布局。
服务写接口仅在回环监听时启用，保留路径检查、文件大小限制与原子写。
